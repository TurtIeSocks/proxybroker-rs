# Changelog

All notable changes to this crate documented here. Format: [Keep a
Changelog](https://keepachangelog.com/en/1.1.0/). Adheres to [SemVer](https://semver.org/).

Entries from 0.4.1 onward are generated by [release-plz](https://release-plz.dev)
from conventional commits. Everything before that was written by hand from the
git history.

## [0.4.1] - 2026-07-29

### Fixed

- `install.sh` requested a checksum filename the release does not publish. It
  derived `<bin>-<ver>-<target>.tar.gz.sha256` by appending to the archive name,
  while releases carry `<bin>-<ver>-<target>.sha256`. The download 404'd and
  `set -eu` aborted, so `curl | sh` failed on every platform in 0.4.0. Both
  names are now built from the same parts, and each download reports which asset
  failed rather than exiting silently.

### Changed

- The container image runs as UID 65532 instead of root. Nothing in it needs
  root: the listener defaults to `:8888` and the binary writes nothing unless
  `--store` points somewhere. A bind mount for `--store sqlite://` must now be
  writable by that UID.

### Internal

- `tests/test_install.sh` asserts the installer's filenames against the naming
  the release workflow produces. Linting the script proved it parses, which is
  what let the 0.4.0 bug ship.
- `cargo audit` gates every dependency against the RustSec advisory database.
- Dependabot covers cargo and github-actions; actions in the publishing
  workflows are pinned by commit SHA.
- Added `SECURITY.md`, including the threat model that separates a misbehaving
  third-party proxy (expected) from a defect in this tool.

## [0.4.0] - 2026-07-28

### Fixed

- CONNECT and SOCKS5 clients received a stream whose TLS had already been
  terminated. `choose_proto` preferred `Proto::Https` for any `Scheme::Https`
  request, but that protocol negotiates a CONNECT *and then a TLS upgrade of its
  own*, so a client's own `ClientHello` was written into the server's TLS
  session as application data. The tunnel died and the client got a 502. Since
  the checker stamps `Proto::Https` on every proxy passing the HTTPS check, this
  affected most HTTPS traffic through `serve`.

### Changed

- A proxy typed only `Https` is now usable as a raw CONNECT tunnel instead of
  being refused. The checker records that type only after a successful `CONNECT`
  followed by a TLS upgrade, so the tunnel capability is proven even when
  `Connect80` was never separately checked. Affects both the local server and
  `RotatingProxyConnector`, which previously discarded such proxies.

## [0.3.0] - 2026-07-22

### Added

- Verify-on-lease: optionally re-probe a proxy with a `CONNECT` tunnel before
  handing it out, so a proxy that died since admission is benched rather than
  served. Off by default; costs up to one timeout per dead proxy skipped.
- Pool priority now uses the persisted success EWMA, which was previously
  computed and then discarded. Warm starts inherit real health history instead
  of treating every stored proxy as unproven.

## [0.2.1] - 2026-07-17

### Fixed

- Release binary matrix: `aarch64-unknown-linux-musl` cross-builds on x86, and
  `x86_64-apple-darwin` builds on Apple Silicon runners. Their nominally native
  runners do not build the crate cleanly.

## [0.2.0] - 2026-07-17

The bulk of the feature surface. Roughly 120 commits.

### Added

- **Serving.** Selection strategies with sticky sessions, health-scored
  selection, rotate-on-error failover with a commit boundary, country filters,
  `--prefer-connect` bias, `--http-allowed-codes` retry on bad upstream status,
  and `--min-queue`/`--backlog` startup controls.
- **Protocols.** A SOCKS5 front-end, upstream proxy auth (SOCKS5 RFC 1929 and
  `Proxy-Authorization`), local-server client auth, `X-Proxy-Info` header
  injection, and the `proxycontrol` history/remove control API.
- **Output.** `--format url`, `csv`, `json-array`, `--output-format` templating,
  `--stats-format json`, and timing percentiles. The `--format json` shape is
  frozen as a v1 contract, guarded by a golden test.
- **Persistence.** A `Store` trait with SQLite and Redis backends, save/load of
  a checked pool, an adaptive re-check scheduler, and live reload of the
  `serve --load` file.
- **Observability.** A Prometheus metrics endpoint, structured per-check tracing
  events with `--log-format json`, judge-probe latency as its own series, and a
  `--progress` bar during `find`.
- **Integrations.** `RotatingProxyConnector` as a hyper-util drop-in with a
  `Broker::rotating()` constructor, an MCP stdio server, and the `top` TUI
  dashboard.
- **Checking.** Judge-less liveness mode, capability profiles, a honeypot/trust
  verdict, configurable retry and backoff, and checking a user-supplied list.
- **Geo.** Region and city from a user-supplied City database, ASN attribution
  from `--asn-db`.
- Bundled provider list expanded from 12 to 50, with 2 dead sources dropped.

### Fixed

- The connector could terminate TLS to the target using the checker's
  accept-all verifier, which would have been a silent MITM hole in real client
  traffic.
- The client's `Proxy-Authorization` header is stripped before forwarding
  upstream. It carries the local server's secret and is hop-by-hop.
- SQLite state uses WAL mode with a busy timeout, so concurrent connections do
  not deadlock or silently drop a re-check outcome.
- Redis TLS enabled so `rediss://` URLs work against managed Redis.
- `max_backoff` is a hard ceiling under jitter rather than a pre-jitter target.
- The trust verdict unions across protocols instead of overwriting.
- `geo.region`/`geo.city` survive the save/load round-trip.
- The unspecified IP sentinel (`0.0.0.0`) is dropped during provider extraction.
- A rotation is counted on an actual proxy switch, not on every retryable
  failure.

## [0.1.1] - 2026-07-16

Documentation only: crates.io badges, and the pre-publish status line removed.

## [0.1.0] - 2026-07-16

Initial release. A from-scratch Rust port of
[proxybroker2](https://github.com/bluet/proxybroker2), covering proxy discovery,
checking, and serving, with the anonymity classification and provider registry
carried over as data rather than subclasses.

Not a translation: no Python source is redistributed, the API was redesigned to
be idiomatic Rust, and defects found in the original were fixed rather than
reproduced. The deviations are recorded in `docs/systematic-refactor/map.md`.

The bundled geo database is DB-IP Country Lite (CC BY 4.0), not MaxMind's
GeoLite2 — see `LICENSE-DATA` and `NOTICE`.
